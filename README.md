矿用设备的控制，司控道岔控制，两种控制方式，矿车司机通过遥控器，315MHz或者433MHz遥控器控制矿井下的道岔转换位置，
或者通过设备上的控制按钮，还有通过运输管理系统远程控制

---

## 硬件

- MCU：**STC8H1K17**，内部 IRC **24.000 MHz**
- 执行机构：**两个气动电磁阀**（一个把道岔推向 A 位，另一个推向 B 位）
- 位置反馈：两个到位开关（低电平有效）
- 遥控：315M / 433M 的 **1527 编码**遥控器（24 位，协议 1）
- 远程：**RS485 / Modbus RTU**（9600 8N1），接运输管理系统

## 引脚定义

| 引脚 | 方向 | 功能 |
|---|---|---|
| P1.3 (OUT1) | 输出 | 电磁阀 A —— 得电把道岔推向 **A 位** |
| P1.4 (OUT2) | 输出 | 电磁阀 B —— 得电把道岔推向 **B 位** |
| P1.5 (OUT3) | 输出 | 岔位 B 指示灯（停在 B 位时亮） |
| P1.6 (OUT4) | 输出 | 岔位 A 指示灯（停在 A 位时亮） |
| P3.1 | 输出 | 板载 LED（低电平点亮）：配对提示、成功慢闪、异常快闪 |
| P3.2 (IN1) | 输入 | 手动转换按钮（低有效，按一次转一次） |
| P3.3 (IN2) | 输入 | 岔位 A 到位信号（低有效） |
| P3.4 (IN3) | 输入 | 岔位 B 到位信号（低有效） |
| P3.5 | 输出 | RS485 方向控制 DE/RE（1=发送，0=接收），DE 与 RE 短接 |
| P3.0 (SW1) | 输入 | 功能键：短按进入遥控配对，长按 6 秒清空全部配对 |
| P3.7 (IN5) | 输入 | 模式选择：0=点动模式，1=全程模式 |
| P1.0 / P1.1 | 串口 | UART2：RxD2 / TxD2（接 485 收发器 RO / DI） |
| P1.2 | 输入 | 无线接收（PWMA 输入捕获解码） |
| P1.7 | 输出 | 蜂鸣器 |

> 现场接线若相反，只需对调 `_main.c` 第 0 层里的 `SOL_TO_A / SOL_TO_B`
> 或 `POS_SIG_A / POS_SIG_B` 两个宏，状态机与指示灯会全部跟着变。

## 控制逻辑

一次转换 = **只给一个阀得电** + **两段确认**：

1. **离开原位**：目标方向的阀得电 → 等"出发位信号消失"（确认道岔真的动了）
2. **到达目标**：阀保持得电 → 等"目标位信号出现" → **立即断电**

到位后两个阀全部断电，不再有任何输出。

- **不到位才返回**：只有"等到达目标位"超时（道岔卡在中间、两端信号都无效）时，
  才给另一个阀得电把道岔推回出发位，然后报错（LED 快闪 + 485 上报）。
  一旦任何一端信号有效（已到位），绝不再反向动作。
- **三种触发源**：手动按钮 (P3.2)、已配对遥控、RS485 上位机命令，
  走同一个入口 `turnout_request()`，保证任何时刻只有一条转换流程在跑。
- 遥控按住不放不会连续触发：一次触发后必须松手静默 300ms 才重新武装。

## 编译与烧录

依赖：**SDCC**（`sdcc` / `packihx` / `makebin` 需在 PATH 中）+ Python（用于中文编码转换）。

```bat
rebuild.bat     :: 清理 out/ → 生成 main.c → 编译，产出 out/main.hex
build.bat       :: 不清理，增量编译
```

- **源码唯一入口是 `_main.c`**。`main.c` 由 `tools/stc-conv_hz.py` 从 `_main.c` 生成，
  **禁止手改**（已在 `.gitignore` 中排除）。
- 烧录用 AiCube-ISP：型号选 **STC8H1K17**，IRC 选 **24.000 MHz**，
  **不要勾选"擦除 EEPROM"** —— 遥控器配对数据和 Modbus 站号都存在里面。

## Modbus RTU 寄存器表

串口参数 **9600 / 8 / N / 1**，从站地址默认 **1**（存在 EEPROM，上位机可改写，掉电保持）。

| 寄存器 | 地址 | 权限 | 含义 |
|---|---|---|---|
| 40001 | 0x0000 | 读 | 状态字：bit0 A有效 bit1 B有效 bit2 位置异常 bit3 转换中 bit4 上次成功 bit5 上次失败 bit6 全程模式 |
| 40002 | 0x0001 | 读 | 当前岔位：0=未知/中间 1=A位 2=B位 |
| 40003 | 0x0002 | 写 | 转岔命令：1=切换 2=转到A 3=转到B（写 0 可撤销未执行的命令） |
| 40004 | 0x0003 | 读/写 | 上次转换结果：0=无 1=成功 2=失败（写 0 清除） |
| 40005 | 0x0004 | 读/写 | 本站地址 1~247（写入后存 EEPROM，立即生效） |
| 40006 | 0x0005 | 读 | 模式：0=点动 1=全程（反映 IN5） |
| 40007 | 0x0006 | 读 | 固件版本，0x0103 = V1.03 |
| 40008 | 0x0007 | 读/写 | 串口接收溢出次数（丢字节），写 0 清零 |
| 40009 | 0x0008 | 读/写 | CRC 校验失败帧数，写 0 清零 |
| 40010 | 0x0009 | 读/写 | 发送看门狗自愈次数，写 0 清零 |

支持功能码 03 / 06 / 10；CRC 错误、非本站地址、广播写按规范静默不应答。

> 后三个是通讯诊断计数：现场若怀疑遥控和总线互相干扰，读这三个数就能分清
> 是"字节没收到"（40008 涨）、"收到了但被干扰破坏"（40009 涨）还是"发送卡死过"（40010 涨）。

## 仿真测试

```bat
python tools/sim_concurrency.py          :: 默认种子
python tools/sim_concurrency.py 12345    :: 指定随机种子
```

`tools/sim_concurrency.py` 是与固件逻辑一一对应的 Python 模型，覆盖 58 项断言：
Modbus 协议与异常码、转岔命令集成、站号延后落盘、发送看门狗自愈、诊断寄存器、
1527 解码（固定协议）、LED 闪烁时序，外加 800 帧随机 fuzz 与 1500 轮压力
（随机插入发送卡死 / 超长噪声帧 / 改站号 / 射频触发）。
